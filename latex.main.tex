	\section{Introdução}
	
	Este relatório técnico descreve a estruturação e a base de desenvolvimento do Sistema de Agendamento de Laboratórios, elaborado como parte das atividades da disciplina de DevSecOps Tools.
	
	O principal objetivo do documento é detalhar os principais aspectos do projeto, contemplando a arquitetura do sistema escolhida, o fluxo de containerização adotado para os ambientes isolados, as práticas e ferramentas de segurança aplicadas e a documentação do site desenvolvido para apresentação do projeto.
	
	O sistema visa promover a inclusão digital de forma estruturada e eficiente, permitindo o gerenciamento e a reserva de computadores em laboratórios através de uma interface web, suportada por um backend robusto e um banco de dados relacional seguro.
	
	Além da aplicação, foi desenvolvido um site utilizando o Google Sites com o objetivo de centralizar as informações do projeto, apresentar suas principais funcionalidades, tecnologias utilizadas, objetivos e cronograma de desenvolvimento.

	\section{Arquitetura do Sistema}
	
	O projeto adota uma arquitetura baseada no padrão MTV (Model-Template-View), provida pelo framework Django (Python), atuando em conjunto com o banco de dados relacional PostgreSQL 15.
	
	A estrutura de diretórios foi devidamente separada para garantir modularidade e escalabilidade:
	
	\begin{itemize}
		
		\item \textbf{agendamentos/}: Representa a aplicação principal (App) do projeto, contendo a lógica de negócios, a definição das tabelas do banco de dados (ORM) em \texttt{models.py}, a interface de administração (\texttt{admin.py}) customizada e o mapeamento das telas e rotas de visualização.
		
		\item \textbf{setup/}: Diretório responsável pela configuração global do projeto Django, contendo as integrações com o banco de dados PostgreSQL e o registro das aplicações instaladas (\texttt{settings.py}), bem como o roteamento principal de URLs.
		
	\end{itemize}
	
	O modelo de dados inicial, nomeado \textit{Computador}, foi estruturado para suportar os agendamentos, contendo campos como identificador único, status, registros de \texttt{data\_hora\_inicio} e \texttt{data\_hora\_fim}, além de observações gerais.
	
	Entre os possíveis estados de um agendamento estão CONFIRMADO, CANCELADO e CONCLUIDO.
	
	O framework Django é responsável pela persistência dos dados e pela integridade relacional através da execução de migrações automáticas (\textit{migrations}).
	
	A utilização do padrão MTV permite separar as responsabilidades da aplicação, facilitando a manutenção do código e permitindo que diferentes componentes do sistema sejam desenvolvidos e modificados de maneira organizada.

	\section{Fluxo de Containerização}
	
	Um dos principais requisitos para garantir a padronização e portabilidade do sistema é a conteinerização. A infraestrutura do projeto foi isolada utilizando Docker e orquestrada pelo Docker Compose.
	
	O fluxo de funcionamento foi dividido em dois serviços independentes, configurados no arquivo \texttt{docker-compose.yml}:
	
	\begin{enumerate}
		
		\item \textbf{Serviço Web (Django):} Responsável por executar a aplicação web em Python. A imagem deste container é construída a partir do arquivo \texttt{Dockerfile}, que realiza a instalação das dependências declaradas no arquivo \texttt{requirements.txt}, configurando o ambiente de execução da aplicação.
		
		\item \textbf{Serviço DB (PostgreSQL):} Um container dedicado ao banco de dados relacional PostgreSQL 15. Os dados são persistidos utilizando volumes gerenciados pelo Docker, garantindo que as informações de agendamentos e cadastros de computadores não sejam perdidas caso o container seja reiniciado.
		
	\end{enumerate}
	
	A utilização de containers permite que o ambiente de desenvolvimento e execução seja padronizado, reduzindo problemas relacionados a diferenças de configuração entre computadores.
	
	O Docker Compose também facilita a inicialização dos serviços necessários para o funcionamento do sistema, permitindo que a aplicação e o banco de dados sejam executados de maneira integrada.

	\section{Ferramentas e Práticas de Segurança (DevSecOps)}
	
	Alinhado aos princípios da disciplina de DevSecOps Tools, o projeto incorpora desde sua base práticas fundamentais para mitigar vazamentos de dados e vulnerabilidades estruturais.
	
	Dentre as práticas implementadas, destacam-se:
	
	\begin{itemize}
		
		\item \textbf{Isolamento de Credenciais (.env):} A gestão de segurança das configurações sensíveis foi feita separando chaves estáticas do código-fonte. Credenciais de acesso ao banco de dados, como usuário, senha e host, e chaves de sessão secretas do Django são injetadas no ambiente por meio de variáveis presentes no arquivo \texttt{.env}.
		
		\item \textbf{Proteção contra Versionamento Indevido (.gitignore):} O arquivo \texttt{.gitignore} foi configurado para impedir que artefatos locais, arquivos de ambiente (\texttt{.env}) e metadados compilados sejam enviados para o repositório no GitHub, protegendo informações restritas do sistema.
		
		\item \textbf{Gestão de Acessos no Painel:} O painel administrativo nativo do Django (\texttt{/admin}) foi customizado para permitir o gerenciamento direto e seguro apenas por administradores autenticados, possuindo filtros de busca e exibição estruturada para não expor a interface do banco diretamente ao usuário comum.
		
	\end{itemize}
	
	A adoção dessas práticas busca incorporar a segurança desde as etapas iniciais do desenvolvimento, seguindo o princípio de integração entre desenvolvimento, operações e segurança.

	% ==================================================
	
	\subsection{Tecnologias Utilizadas}
	
	Na página inicial do site são apresentadas as principais tecnologias utilizadas no desenvolvimento do LabManager:
	
	\begin{itemize}
		
		\item \textbf{Django 4.2:} framework utilizado no desenvolvimento do backend da aplicação.
		
		\item \textbf{Python 3.11:} linguagem de programação utilizada no desenvolvimento do sistema.
		
		\item \textbf{PostgreSQL:} sistema gerenciador de banco de dados relacional utilizado para armazenamento das informações.
		
		\item \textbf{Docker:} tecnologia utilizada para a criação e execução dos containers da aplicação.
		
		\item \textbf{Flatpickr JS:} biblioteca JavaScript utilizada para auxiliar na seleção e manipulação de datas e horários.
		
	\end{itemize}
	
	A utilização conjunta dessas tecnologias permite estruturar uma aplicação web com separação de responsabilidades, persistência de dados, isolamento de ambientes e recursos voltados à experiência do usuário.

	\subsection{Funcionalidades Apresentadas}
	
	O site apresenta quatro funcionalidades principais do LabManager.
	
	% --------------------------------------------------
	% 5.3.1
	% --------------------------------------------------
	
	\subsubsection{Agendamento Inteligente}
	
	A funcionalidade de agendamento permite o controle dos horários de utilização dos laboratórios.
	
	O sistema apresenta informações em tempo real, realiza o cálculo automático dos custos por hora e possui mecanismos visuais para impedir ou indicar conflitos entre horários.
	
	% --------------------------------------------------
	% 5.3.2
	% --------------------------------------------------
	
	\subsubsection{Inventário e Softwares}
	
	O módulo de inventário tem como objetivo realizar o gerenciamento do parque de computadores dos laboratórios.
	
	A documentação também apresenta o controle dos pacotes de software instalados em cada máquina e um painel destinado às solicitações de novas instalações.
	
	% --------------------------------------------------
	% 5.3.3
	% --------------------------------------------------
	
	\subsubsection{Controle de Acesso (RBAC)}
	
	O projeto utiliza o conceito de RBAC (\textit{Role-Based Access Control}), permitindo a divisão dos usuários em diferentes níveis de acesso.
	
	Entre os perfis apresentados estão:
	
	\begin{itemize}
		
		\item Alunos/Comunidade;
		
		\item Técnicos;
		
		\item Administradores.
		
	\end{itemize}
	
	Essa divisão permite estabelecer diferentes permissões de acordo com as responsabilidades de cada usuário, além de contar com um fluxo de aprovação de contas.
	
	% --------------------------------------------------
	% 5.3.4
	% --------------------------------------------------
	
	\subsubsection{Gestão Financeira}
	
	A gestão financeira permite apresentar aos usuários os custos acumulados relacionados à utilização dos recursos.
	
	Para os gestores, são disponibilizados relatórios consolidados relacionados ao faturamento e aos lucros, permitindo uma visão administrativa e financeira do funcionamento dos laboratórios.

	\subsection{Objetivo do LabManager}
	
	O LabManager foi desenvolvido para automatizar e otimizar o fluxo de utilização de laboratórios de informática e espaços compartilhados de tecnologia da informação.
	
	A proposta é centralizar reservas, controle de ativos e suporte técnico em uma única interface, reduzindo processos manuais e proporcionando maior controle administrativo e financeiro.
	
	A centralização dessas informações permite melhorar a organização dos recursos disponíveis e facilitar o gerenciamento dos laboratórios.

	\section{Conclusão}
	
	O relatório demonstrou a adequação do sistema de agendamentos às boas práticas de Engenharia de Software e DevSecOps.
	
	A separação de responsabilidades por meio da arquitetura baseada em Django, associada à utilização de containers com Docker Compose, contribui para simplificar as fases de desenvolvimento, configuração e implantação do sistema.
	
	O uso de variáveis de ambiente assegura que as regras de segurança sejam respeitadas, evitando a exposição de chaves e senhas da infraestrutura.
	
	As práticas relacionadas ao controle de acesso, proteção de credenciais e utilização do arquivo \texttt{.gitignore} também contribuem para estabelecer uma base mais segura para o projeto.
	
	Além da aplicação, a criação do site LabManager permitiu centralizar e apresentar as principais informações do sistema, incluindo suas tecnologias, funcionalidades, objetivos e cronograma de desenvolvimento.
	
	Com isso, o projeto possui não apenas uma estrutura técnica baseada em Django, PostgreSQL e Docker, mas também uma documentação complementar voltada à apresentação e compreensão da solução.
	
	O conjunto dessas características forma um alicerce organizado para as próximas etapas de desenvolvimento do sistema de agendamento de laboratórios, permitindo sua evolução com foco em segurança, organização, escalabilidade e facilidade de manutenção.
